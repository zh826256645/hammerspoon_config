# Time Machine 备份后安全弹出硬盘

状态：完整方案已获用户确认，已实现并在本机启用；验证范围见文末。

## 目标

每次 Time Machine 成功备份后，自动安全弹出备份硬盘，减少早晨忘记退出就拔线的情况。术语见根目录 `CONTEXT.md`。

## 已确认的行为

1. 每次成功备份都处理，不限定夜间。
2. 仅处理「zhonghao」所在的整块外置备份硬盘。按稳定卷身份识别，并在操作前确认对应物理盘；不依赖可能变化的磁盘编号或仅凭名称选择设备。
3. 备份失败或取消时保持连接，并通知备份未完成。无法确认成功时不得按成功处理。
4. 备份成功后仅尝试普通安全弹出。若有程序占用或其他弹出错误，保持连接并通知用户处理，不强制弹出，不持续自动重试。
5. 启用自动化以及每次启动或重载时建立观察基线，不因已经存在的旧成功备份立即弹出硬盘；只响应之后识别到的新成功备份。
6. 沿用当前睡眠设置。系统睡眠期间无法持续检查时，唤醒后补查新的备份结果；不保证唤醒之前已完成弹出。
7. 安全弹出成功后通知：“备份完成，硬盘已安全弹出，可以拔线”。只有确认整块硬盘安全弹出后才能发送此提示。

## 使用边界

- 使用当前 Hammerspoon 配置承载自动化；现有 Time Machine 备份频率和电源要求不在本次修改范围内。
- 安全弹出后，下次备份前需要重新插入硬盘。
- 启动或重载时的基线规则优先：不以重载前的旧结果触发弹出。
- 同一次备份结果只处理一次，避免重复弹出和重复通知。
- 不修改备份内容，不自动开始或取消备份，不处理其他硬盘。

## 实施验收场景

- 新备份成功且硬盘空闲：整盘安全弹出，收到可以拔线的通知。
- 备份失败或取消：硬盘保持连接，收到备份未完成通知。
- 新备份成功但弹出被拒绝：硬盘保持连接，收到弹出失败通知，无强制弹出。
- 启动或重载时已有旧备份：不立即弹出；之后的新成功备份可以正常触发。
- 启用后的新成功备份发生在睡眠期间：唤醒补查后安全弹出；重复检查不重复通知。
- 目标盘缺席或连接其他盘：不弹出其他设备。

## 实现与验证

- Hammerspoon 每 30 秒通过异步任务检查，系统唤醒、屏幕唤醒或解锁时也触发补查。
- Python 3 标准库脚本通过系统偏好查询取得目标的尝试日期、成功备份日期和结果，并读取 `tmutil status -X`。不直接读取受保护的偏好文件。
- 连续两次空闲检查取得相同结果后，要求结果码为成功、成功备份日期晚于观察基线且不早于本次尝试，才能进入弹出流程。
- 通过备份卷 UUID、APFS 物理存储和父物理盘关系解析目标；弹出前重新确认身份及备份状态。仅调用普通 `diskutil eject`，以整盘弹出命令成功完成作为系统安全移除确认，不要求磁盘编号立即从设备列表消失。
- 19 项 Python 模拟测试已通过，覆盖备份结果、去重、唤醒补查、占用失败、设备身份保护和弹出成功后设备列表仍残留的情况；未在测试中执行真实弹出。
- Hammerspoon 的真实后台只读探测已成功，确认可以读取当前正在运行的备份；不需要为此新增完整磁盘访问权限。
- Lua 模拟生命周期测试和相关配置语法检查通过，覆盖单任务执行、唤醒触发、读取错误通知去重与停止后的过期回调隔离。
- 已在本机 `config.lua` 中启用并重载 Hammerspoon，确认监控正在运行、已建立基线且无状态读取错误。启用时已有一次备份正在运行，监控已将它纳入观察。
- Hammerspoon 后台的只读物理盘探测通过，已确认目标卷能解析至当前外置物理盘；未执行卸载或弹出。
- 初次启用时未为测试手工触发弹出、取消或启动备份。

## 2026-10-19 弹出成功后的误报修复

- 用户报告 02:36:50 出现“系统尚未确认整块硬盘退出”的提示。系统日志在 02:36:50.380 和 02:36:50.820 明确记录整盘弹出成功；后台代码也已收到 `diskutil eject` 的成功退出状态。
- 原因是额外检查要求磁盘编号立即从 `diskutil list` 消失，错误地将仍在列表中的设备记录判作弹出失败。系统安全弹出确认与设备编号消失不是同一个条件。
- 移除该后置检查，保留设备身份核对、备份结果复查、普通整盘弹出，以及系统拒绝或超时的错误处理。
- 回归测试在旧代码上复现相同报错，修复后通过；测试使用模拟命令结果，没有重新挂载或弹出实际硬盘。
